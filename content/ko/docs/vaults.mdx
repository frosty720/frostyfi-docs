# Vault

ThirdWeb Vault를 통한 안전한 키 커스터디와 서명.

## 개요

Vault는 서버 지갑을 보관하여 프라이빗 키가 결코 안전한 인프라(AWS Nitro
Enclaves)를 떠나지 않도록 합니다. **Vault 노드**는 지갑 관리와 서명을 처리합니다.
잔액을 읽거나 자금을 전송하지는 **않습니다** — 그것은 [EVM](/docs/workflows)과 Solana
노드의 역할이며, 이들은 Vault를 통해 트랜잭션에 서명합니다.

## 지원되는 작업

| 작업 | 설명 |
|-----------|-------------|
| `getWallet` | 구성된 서버 지갑 가져오기 |
| `createEoa` | 새 EOA 서버 지갑 생성 |
| `listEoas` | EOA 서버 지갑 목록 조회 |
| `signMessage` | 임의 메시지 서명 |
| `signTypedData` | EIP-712 타입 데이터 서명 |
| `signTransaction` | 트랜잭션 서명 |
| `signAuthorization` | EIP-3009 / 인가 페이로드 서명 |
| `signStructuredMessage` | 구조화된 메시지 서명 |
| Solana | `createSolanaAccount`, `listSolanaAccounts`, `signSolanaTransaction`, `signSolanaMessage` |

## 지원되는 체인

- Ethereum
- Base
- Arbitrum
- Polygon
- Optimism
- 그리고 Thirdweb를 통한 더 많은 체인

## 워크플로우에서 사용하기

서버 지갑으로 서명하려면 **Vault 노드**를 추가하세요 — 예를 들어, 메시지 서명:

```json
{
  "type": "vault",
  "operation": "signMessage",
  "message": "gm"
}
```

자금을 이동하거나 컨트랙트를 호출하려면 **EVM**(또는 **Solana**) 노드를 사용하세요 —
이는 서명을 위해 Vault와 결합되므로, 키는 여전히 결코 Vault를 떠나지 않습니다.

## 보안

- 프라이빗 키는 결코 Thirdweb 인프라를 떠나지 않음
- 사용자 범위 격리
- 안전한 실행을 위한 AWS Nitro Enclaves
