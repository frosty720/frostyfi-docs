# Frosty Engine

自動化されたバックグラウンドでのワークフロー実行。

## 概要

Frosty Engine は、スケジュールまたはウェブフック経由でワークフローを実行します。Pro および Enterprise ユーザーが利用できます。

デプロイされた各ワークフローには、そのバックグラウンド実行を提示する **Runs** パネルがあります — トリガー
タイプ（ウェブフック / スケジュール）、ステータス、レイテンシ — そのため、自動化がどう
機能しているかを一目で確認できます。

![Runs パネル — ステータスとレイテンシ付きのバックグラウンド実行](/screenshots/runs-panel.png)

## 機能

- **スケジュール済みワークフロー**：cron ベースの自動化
- **ウェブフックトリガー**：ワークフローをトリガーする HTTP エンドポイント
- **ティア検証**：実行ごとのサブスクリプションチェック
- **Vault 連携**：バックグラウンドでのブロックチェーン操作
- **実行履歴**：完全な監査証跡

## デプロイ状態

| 状態 | Scheduler | Webhook |
|-------|-----------|---------|
| 未デプロイ | ❌ | ❌ |
| デプロイ済み | ✅ | ✅ |
| 一時停止 | ⏸️ | ❌ |
| 停止 | ❌ | ❌ |

## API エンドポイント

### デプロイ
- `POST /api/deploy` - ワークフローをデプロイ
- `POST /api/deployments/:id/pause` - 一時停止
- `POST /api/deployments/:id/resume` - 再開
- `DELETE /api/deployments/:id` - 削除

### 実行
- `POST /api/execute` - 手動実行
- `GET /api/executions/:id` - ステータスを取得

### ウェブフック
- `POST /webhooks/:id` - デプロイされたワークフローをそのウェブフック経由でトリガー

> cron スケジュールとウェブフックは、ワークフローの **デプロイ** の一部として構成されます（スケジューラ
> とウェブフックレシーバーがデータベースからそれらを読み取ります） — 別途の
> スケジュール管理エンドポイントはありません。

## セキュリティ

- JWT 認証が必須
- サブスクリプションティアの検証
- レート制限が有効
- ウェブフックシークレットの検証

## 要件

- Pro（$25/月）または Enterprise（$99/月）のサブスクリプション
- ジョブキュー用の Redis
- メインアプリと共有のデータベース
