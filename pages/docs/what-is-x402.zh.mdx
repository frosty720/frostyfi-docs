# x402 是什么？

**x402 是一个开放支付协议，让软件在发出 HTTP 请求的那一刻就完成付费。** 它重新启用了长期闲置的
`402 Payment Required` 状态码：服务器用 `402` 和报价回应请求，客户端签署一笔稳定币转账，然后
带着付款凭证重发同一个请求。

不需要 API 密钥，不需要注册账户，不需要订阅，也不需要联系销售。**付款本身就是凭证。**

这一点对 **AI 代理** 尤其关键：代理终于可以自己购买所需的数据和推理，而不必等人类先去申请密钥。

## 一次 x402 请求的完整流程

1. 客户端照常调用一个付费接口。
2. 服务器返回 **`402 Payment Required`**，并附上 `accepts` 列表——金额、资产、网络、收款地址。
3. 客户端将报价与自己的支出上限比对，然后为该金额签署一份
   **EIP-3009 `TransferWithAuthorization`**。
4. 客户端重发**完全相同**的请求，并在 `PAYMENT-SIGNATURE` 请求头中携带已签名的授权。
5. 服务器（或结算方 facilitator）在链上完成结算，并返回真正的响应。

两个细节承担了大部分工作。签名的是一份**授权**而非交易，因此由*服务器*提交上链并支付 gas，
代理无需持有任何原生 gas 代币。其次，第 4 步是第 1 步逐字节的重放，所以接入 x402 不需要重新
设计现有 API。

## 成本：说实话

x402 **不会让推理变便宜**，单次调用通常反而**更贵**。

典型的 x402 接口按请求收取固定费用，而这笔费用往往远高于底层算力成本——服务成本不到一美分的
调用，可能被收取三分之一美分甚至更多。**如果你优化的目标是价格，向服务商预充值的账户依然更划算。**

x402 换来的不是价格，而是**自主性**。持有 USDC 的代理可以向任何支持 x402 的服务商付费，无需账户、
无需轮换密钥、无需人工介入。对于一个无人值守持续运行的代理来说，这就是「能继续跑」和「卡住」的
区别。

对把 x402 包装成「省钱方案」的说法要保持警惕。它是一种**新能力，不是折扣**。

## x402 在 FrostyFi 中的实现

FrostyFi 同时支持协议的**付费端**与**收费端**。

**付费端。** **x402 Pay** 节点可以调用任意 x402 接口并自行完成挑战。你只需提供 URL 和支出上限，
402 解析、签名、重放都由节点处理。私钥保存在 [thirdweb Vault](/docs/vaults) 中，工作流永远接触
不到私钥；上限校验发生在签名**之前**，因此恶意或贪婪的接口无法掏空钱包。

**收费端。** 把工作流发布为[代理](/docs/agents)并设定每次调用的价格。调用方用 USDC 付费，结算在
链上完成，代理还可以拥有 [ERC-8004](/docs/agents#erc-8004-identity--reputation) 链上身份与声誉。

两端合起来就闭环了：赚取 USDC 的代理可以用 USDC 购买自己的推理，而这两笔交易你都不必参与。

## 常见问题

**x402 是区块链或代币吗？**
都不是。它是一种 HTTP 约定。结算发生在接口所接受的链上，最常见的是 Base 上的 USDC，但并不存在
所谓「x402 代币」。

**代理需要准备 gas 吗？**
不需要。EIP-3009 让付款方只需签署授权，交易的提交与 gas 由服务器或结算方承担。

**接口会不会超额收费？**
它可以*索要*任意金额。正确实现的客户端会在签名前把索要金额与硬性上限比对。FrostyFi 的节点在超过
上限时直接拒绝，根本不会进入签名环节。

**使用哪种稳定币？**
实践中是 USDC，多数在 Base 上。不过协议本身与资产、链无关。

**需要写代码吗？**
在 FrostyFi 中不需要。x402 Pay 是一个拖到画布上的节点。
