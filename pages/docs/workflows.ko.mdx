# 워크플로우 & 노드 라이브러리

**워크플로우**는 드래그 앤 드롭 캔버스(`@xyflow/react` 기반)에서 구축하는 방향
그래프입니다. 각 **노드**는 하나의 단계입니다. 각 **엣지**는 한 노드의 출력을 다음
노드의 입력으로 전달합니다. 이 페이지에서는 데이터가 어떻게 흐르는지, 모든 노드
유형, 그리고 Frosty Engine으로 워크플로우를 백그라운드에서 실행하는 방법을 다룹니다.

![캔버스 위의 워크플로우 — Input → HTTP → LLM → Output, 문서 노트 포함](/screenshots/workflow-canvas.png)

## 데이터가 흐르는 방식

모든 워크플로우는 동일한 형태를 따릅니다:

```
Input ──► (any nodes) ──► Output
```

- **모든 워크플로우는 Input 노드에서 시작해야 합니다.** 이는 진입점이자 검증
  게이트입니다 — 웹훅과 스케줄러 트리거는 그 *다음에* 연결됩니다.
- 각 노드는 상위 노드의 출력에서 읽고 자신의 출력을 생성하며, 하위 노드가 이를 참조할
  수 있습니다.
- **Output**은 워크플로우가 반환하는 최종 결과를 생성합니다(채팅으로, 웹훅 호출자에게,
  또는 A2A 결제자에게).

중간 값을 형성하고 이름 붙이려면 **Template**과 **Set** 노드를, 분기하려면
**Condition**을, 배열을 순회하려면 **Loop**을, 병렬 경로를 재결합하려면 **Merge**를
사용하세요.

## 노드 라이브러리

### 핵심 흐름

| 노드 | 하는 일 |
|------|--------------|
| **Input** | 진입점. 실행을 위한 초기 데이터를 받습니다. 필수. |
| **Output** | 종료점. 워크플로우의 최종 결과를 생성합니다. |
| **Condition** | 비교에 기반한 if/else 분기. |
| **Set** | 이후 노드가 사용할 수 있도록 명명된 변수에 값을 할당합니다. |
| **Merge** | 여러 병렬 실행 경로의 데이터를 결합합니다. |
| **Loop** | 배열을 순회하며 항목마다 서브 워크플로우를 실행합니다. |
| **Wait** | 설정된 시간 동안 실행을 지연합니다. |
| **Template** | 이전 출력에서 `{{variable}}` 치환으로 텍스트를 생성합니다. |
| **Note** | 문서화/주석 노드(실행에 영향 없음). |

### AI

| 노드 | 하는 일 |
|------|--------------|
| **LLM** | 프롬프트로 AI 모델을 호출합니다(OpenRouter를 통해 라우팅). |
| **Agent** | 도구, 메모리, 다단계 추론을 갖춘 자율 AI 에이전트 단계. |
| **Tool** | [MCP](/docs/mcp) 도구를 실행합니다. |

### 웹 & 통합

| 노드 | 하는 일 |
|------|--------------|
| **HTTP** | 모든 엔드포인트로 REST API 요청을 보냅니다. |
| **Webhook** | 인바운드 HTTP 요청으로 워크플로우를 트리거합니다(Frosty Engine 참조). |
| **Scheduler** | cron 스케줄로 워크플로우를 트리거합니다(Frosty Engine 참조). |
| **EmailSend** | SMTP로 이메일을 보냅니다. |
| **Telegram** | Telegram 채팅/채널로 메시지를 보냅니다. |
| **Discord** | 웹훅을 통해 Discord 채널로 메시지를 보냅니다. |
| **Twilio** | Twilio를 통해 SMS 및 WhatsApp 메시지를 보냅니다. |
| **RSS** | RSS/Atom 피드를 읽고 파싱합니다. |
| **Twitter** | Twitter/X API로 게시하고 상호작용합니다. |
| **ChainGPT** | ChainGPT AI 기반 Web3 도구. |

### 미디어

| 노드 | 하는 일 |
|------|--------------|
| **Image** | 프롬프트로 이미지를 생성합니다(OpenRouter를 통해 라우팅). |
| **Video** | 프롬프트로 비디오를 생성합니다(OpenRouter를 통해 라우팅). |
| **Voice** | 텍스트-음성 변환 및 음성-텍스트 변환(TTS / STT). |
| **File** | 파일 첨부를 다룹니다 — 노드 간에 파일을 읽고, 쓰고, 전달합니다. |

### 코드

| 노드 | 하는 일 |
|------|--------------|
| **Code** | 샌드박스 처리된 JavaScript를 실행합니다. Frosty Engine에서 코드는 안전한 실행을 위해 `isolated-vm` 샌드박스 내에서 실행됩니다. |

### 블록체인

| 노드 | 하는 일 |
|------|--------------|
| **Vault** | ThirdWeb Vault를 통한 키 커스터디 + 서명 — 서버 지갑을 관리하고(`getWallet`, `createEoa`, `listEoas`) 서명합니다(`signMessage`, `signTypedData`, `signTransaction`, `signAuthorization`), 그리고 Solana 대응 기능도 포함합니다. 키는 Vault에 보관되며 원시 프라이빗 키로 붙여넣는 일은 결코 없습니다. [Vault](/docs/vaults)를 참조하세요. |
| **EVM** | ThirdWeb v5 SDK를 통한 EVM 작업 — 잔액 읽기, 컨트랙트 읽기/쓰기, 트랜잭션 전송, ERC-20/721/1155 전송, ENS 해석, Uniswap V3 견적, 브리지 상태, 컨트랙트 배포, 그리고 **x402 결제**(`x402Payment`, `x402RetryWithPayment`). 멀티체인: ThirdWeb를 통한 1700개 이상 체인. |
| **Solana** | `@solana/web3.js`를 통한 Solana 작업. |

### DeFi & 트레이딩

| 노드 | 하는 일 |
|------|--------------|
| **Uniswap** | EVM 체인에서의 Uniswap 스왑 및 견적. |
| **SushiSwap** | EVM 체인에서의 SushiSwap 스왑 및 견적. |
| **PancakeSwap** | EVM 체인에서의 PancakeSwap 스왑 및 견적. |
| **Jupiter** | Jupiter 애그리게이터를 통한 Solana 스왑 및 견적. |
| **Hyperliquid** | Hyperliquid 무기한 선물/마켓 — 가격, 오더북, 포지션(그리고 트레이딩). |

> **원시 키가 아닌 Vault.** FrostyFi는 프라이빗 키나 시드 문구를 붙여넣도록 요청하지
> 않습니다. 블록체인 쓰기 작업은 ThirdWeb Vault를 통해 서명되므로, 서명 자료는
> Vault 안에 머물며 워크플로우 설정 밖에 있습니다.

## Frosty Engine으로 배포 & 스케줄링

캔버스는 구축을 위한 것입니다. 워크플로우를 **브라우저를 열어두지 않고 백그라운드에서
실행하려면** 각 노드 유형을 헤드리스 실행에 최적화된 실행기로 돌리는 Express 기반 실행
백엔드인 **Frosty Engine**에 배포합니다.

워크플로우가 스스로 실행되게 하는 트리거 유형은 두 가지입니다:

- **Scheduler (cron)** — 반복 스케줄로 워크플로우를 실행합니다. cron 스케줄은
  지속적입니다: 데이터베이스에 저장되어 엔진이 재시작될 때 다시 로드됩니다.
- **Webhook** — 외부 서비스가 웹훅 URL로 POST할 때 워크플로우를 실행합니다.
  웹훅 호출은 웹훅별 시크릿으로 인증됩니다.

백그라운드 실행(Frosty Engine)은 **Pro / Enterprise** 기능입니다 —
[요금제](/docs/pricing)를 참조하세요.

> **참고:** 반복 cron 스케줄은 엔진 재시작에도 살아남습니다. 일회성(지연) 스케줄과
> 진행 중인 실행은 현재 메모리에 보관되며 재시작 후 재개가 보장되지 않습니다 —
> 지속적 작업 큐잉은 로드맵에 있습니다. 시간이 중요한 자동화에는 반복 스케줄을
> 사용하는 것이 좋습니다.
