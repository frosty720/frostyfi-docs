# 핵심 개념

FrostyFi에는 모두 "AI"와 관련되어 있어 혼동하기 쉬운 몇 가지 구성 요소가 있습니다. 이
페이지는 각각을 정확히 정의하고 — 무엇보다 중요하게 — **어시스턴트**와 **에이전트**
사이의 경계를 명확히 그립니다.

## 워크플로우

**워크플로우**는 대표 기능입니다: 드래그 앤 드롭 캔버스에서 구축하는 비주얼 노드 기반
자동화입니다. 워크플로우는 **엣지**(데이터 흐름)로 연결된 **노드**(단계)의 방향
그래프입니다. 항상 **Input** 노드에서 시작하고 **Output** 노드에서 끝납니다. 그 사이에
LLM 호출, HTTP 요청, 조건, 코드, 블록체인 작업, 루프, 통합을 연결합니다.

워크플로우는 노드 + 엣지로 데이터베이스에 저장됩니다. 세 가지 방식으로 실행할 수 있습니다:

- **인라인** — 채팅에서 `@멘션`되어 도구로 실행됩니다.
- **백그라운드** — [Frosty Engine](/docs/workflows#frosty-engine)에 cron 스케줄로
  또는 웹훅을 통해 배포됩니다.
- **에이전트로** — 외부 호출자가 호출할 수 있도록 게시됩니다(아래 에이전트 참조).

전체 노드 라이브러리는 [워크플로우 & 노드](/docs/workflows)를 참조하세요.

## 어시스턴트

**어시스턴트**는 **추론 채팅 전문가**입니다. 구성된 페르소나 — 역할/전문성, 시스템
프롬프트, 스킬 세트, 도구 세트 — 로 생각하면 됩니다. `@`로 채팅에서 불러올 수 있습니다.

주요 속성:

- **모델에 구애받지 않음.** 어시스턴트는 하나의 모델에 묶이지 않고, 선택기에서 여러분이
  선택한 어떤 모델에서든 실행됩니다.
- 채팅에서 **`@멘션 가능`**. 어시스턴트를 멘션하면 그 페르소나와 스킬이 대화에 주입됩니다.
- **배포할 수 없음.** 어시스턴트는 채팅 런타임 안에 존재합니다 — 헤드리스 백그라운드
  런타임이 없으므로 직접 x402/A2A/ERC-8004 엔드포인트로 전환되지 *않습니다*.
  어시스턴트의 동작을 배포 가능한 단위로 필요로 한다면 워크플로우에 구축하세요
  (**Agent 노드**를 통해 워크플로우가 어시스턴트 스타일의 추론을 내장할 수 있습니다).

## 에이전트

**에이전트**는 **배포된 워크플로우 에이전트**입니다. 온체인 아이덴티티를 갖춘 라이브
호출 가능 엔드포인트로 게시된 워크플로우입니다. FrostyFi의 모델에서 *"워크플로우
에이전트"와 "A2A 에이전트"는 동일한 것*입니다 — 배포용으로 플래그된 동일한 레코드입니다.

에이전트는 다음을 제공합니다:

- [A2A](/docs/agents#a2a-protocol) 엔드포인트와 검색 가능한 **에이전트 카드**.
- 선택적 [x402](/docs/agents#x402-payments) 호출당 USDC 결제.
- 선택적 [ERC-8004](/docs/agents#erc-8004-identity--reputation) 온체인 아이덴티티 및
  평판.
- [마켓플레이스](/docs/agents#marketplace) 등록.

### 어시스턴트 vs 에이전트 — 정확한 구분

| | **어시스턴트** | **에이전트** |
|---|---|---|
| 무엇인가 | 추론 채팅 페르소나 | 배포된 워크플로우 |
| 워크플로우 기반? | 아니오(`workflowId`가 null) | 예(`workflowId`를 가짐) |
| 어디서 실행되는가 | 채팅 런타임 내부 | 헤드리스, Frosty Engine에서 |
| 채팅에서 `@멘션 가능`? | 예 | 아니오 — 에이전트 엔드포인트로 호출하거나 워크플로우를 실행 |
| 배포 가능? | 아니오 | 예 — 그것이 바로 에이전트로 만드는 것 |
| x402 / A2A / ERC-8004? | 아니오 | 예 |

간단히 말하면: **어시스턴트는 채팅 안에서 생각하기 위한 것이고, 에이전트는 다른 사람들이
호출하고 비용을 지불할 수 있는 배포된 워크플로우를 실행하기 위한 것입니다.** 두 표면 모두
*워크플로우를 통해* 동일한 수익화 경로를 얻습니다 — 어시스턴트의 기능을 워크플로우로
구성한 다음 그 워크플로우를 에이전트로 배포하면 됩니다.

## 스킬

**스킬**은 **어시스턴트에 주입되는 지침 전용 문서**입니다. 스킬은 코드도 도구도
아닙니다 — 어시스턴트의 시스템 프롬프트에 추가되는 안내 블록(모범 사례, 절차, 도메인
지식)입니다. 사용자의 요청이 스킬과 일치하면 어시스턴트는 그 안내를 따릅니다.

스킬은 소프트웨어를 작성하지 않고도 어시스턴트에게 무언가를 *어떻게* 하는지 가르치는
방법입니다. 어시스턴트 편집기에서 스킬을 어시스턴트에 첨부합니다.

## MCP 서버

**MCP 서버**([Model Context Protocol](/docs/mcp))는 **도구**의 외부 소스입니다.
MCP 서버를 연결하면 채팅과 어시스턴트에 호출 가능한 도구 세트(예: 시장 데이터, 결제,
웹 페치)가 제공됩니다.

MCP는 **원격 전용**입니다 — 원격(HTTP/SSE) MCP 서버에 연결합니다. 마켓플레이스는
검증된 원격 서버(예: CoinGecko, Alpha Vantage, Stripe, Etherscan, Blockscout)를 제공합니다.

## 템플릿

**템플릿**은 **복제하여 사용하는 워크플로우**입니다. 템플릿 갤러리에는 미리 구축된
공개 워크플로우가 있습니다. **Use template**을 클릭하면 그중 하나를 여러분의
워크스페이스로 복사합니다(새 노드 ID와 함께) 실행하고 커스터마이즈할 수 있게 됩니다.
템플릿은 시작하는 가장 빠른 방법입니다 —
[시작하기](/docs/getting-started#4-create-your-first-workflow-from-a-template)를 참조하세요.
