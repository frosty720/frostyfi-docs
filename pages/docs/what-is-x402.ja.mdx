# x402とは？

**x402は、HTTPリクエストを送るその瞬間に支払いを完結させるオープンな決済プロトコルです。**
長く使われてこなかった `402 Payment Required` ステータスコードを再利用します。サーバーは
リクエストに対して `402` と価格を返し、クライアントはステーブルコインの送金に署名し、支払い証明を
付けて同じリクエストを再送します。

APIキーも、アカウント登録も、サブスクリプションも、商談も不要です。**支払いそのものが認証情報**
になります。

これが最も効いてくるのが **AIエージェント** です。人間が事前にAPIキーを発行しなくても、エージェント
自身が必要なデータや推論を購入できるようになります。

## x402リクエストの流れ

1. クライアントが有料エンドポイントを通常どおり呼び出す。
2. サーバーが **`402 Payment Required`** と `accepts` リスト（金額・資産・ネットワーク・送金先
   アドレス）を返す。
3. クライアントは自身の上限額と照合したうえで、その金額ちょうどの
   **EIP-3009 `TransferWithAuthorization`** に署名する。
4. クライアントは `PAYMENT-SIGNATURE` ヘッダーに署名済みの認可を載せ、**まったく同じリクエスト**
   を再送する。
5. サーバー（またはファシリテーター）がオンチェーンで決済を実行し、本来のレスポンスを返す。

重要な点が2つあります。署名するのはトランザクションではなく **認可（authorization）** なので、
実際にトランザクションを送信してガス代を払うのは *サーバー側* です。つまりエージェントはガス
トークンを保有する必要がありません。もう1つは、手順4が手順1のバイト単位で同一な再送であるため、
既存のAPIを設計し直すことなくx402を組み込めることです。

## コストについて（正直に）

x402は推論を**安くする仕組みではありません**。1回あたりのコストは、たいていの場合**割高**になります。

一般的なx402エンドポイントはリクエストごとに定額の手数料を課しますが、この手数料は実際の計算コスト
を大きく上回ることがあります。1回あたり1セント未満で提供できる処理に、0.3セント以上の手数料が
乗ることも珍しくありません。**価格だけを最適化するなら、プロバイダーへの前払いアカウントのほうが
依然として有利です。**

x402で得られるのは価格ではなく **自律性** です。USDCを保有するエージェントは、x402に対応した
あらゆるプロバイダーに対して、アカウントもキー管理も人間の承認もなしに支払えます。無人で動き続ける
エージェントにとって、これは「動作する」か「停止する」かの差になります。

x402を「コスト削減策」として売り込む説明には注意してください。これは**割引ではなく、新しい能力**です。

## 実際に決済されたトランザクション

図解ではなく、実際のログから。

FrostyFiのワークフローが有料の推論エンドポイントを呼び出し、エンドポイントは `402` を返しました。
エージェントのVault管理ウォレットが上限 `$0.05` の範囲でEIP-3009の認可に署名し、リクエストを再送。
レスポンスが返り、送金は **Base** 上で決済されました。

| 項目 | 値 |
| --- | --- |
| 支払額 | `$0.00333` USDC |
| ネットワーク | `eip155:8453`（Base） |
| 決済トランザクション | [`0x17942efd…4f2d64254`](https://basescan.org/tx/0x17942efd0ae1fb7a88b8ce0e605e1beb53e90c2f1ba0770c0874e3a4f2d64254) |
| 所要時間 | 7.02秒 |

このフローのどこにもAPIキーは存在しません。エージェントが自分で推論を買ったということです。

## FrostyFiにおけるx402

FrostyFiはx402の**支払う側**と**課金する側**の両方に対応しています。

**支払う側。** **x402 Pay** ノードは任意のx402エンドポイントを呼び出し、402チャレンジを自動で
処理します。設定するのはURLと上限額だけで、402の解析・署名・再送はノードが行います。鍵は
[thirdweb Vault](/docs/vaults) に保管され、ワークフローが秘密鍵に触れることはありません。上限
チェックは署名の**前**に実行されるため、不正なエンドポイントがウォレットを空にすることはできません。

**課金する側。** ワークフローを[エージェント](/docs/agents)として公開し、1コールあたりの価格を
設定できます。呼び出し側はUSDCで支払い、決済はオンチェーンで行われ、エージェントは
[ERC-8004](/docs/agents#erc-8004-identity--reputation) のオンチェーンIDと評価を持てます。

この2つが揃うとループが閉じます。USDCを稼ぐエージェントが、そのUSDCで自分の推論を買う。
そのどちらの取引にも、あなたは関与していません。

## よくある質問

**x402はブロックチェーンやトークンですか？**
どちらでもありません。HTTPの規約です。決済はエンドポイントが受け付けるチェーン上で行われ、
多くの場合Base上のUSDCですが、「x402トークン」は存在しません。

**エージェントにガス代は必要ですか？**
不要です。EIP-3009により、支払い側は認可に署名するだけで、トランザクションの送信とガス代の負担は
サーバーまたはファシリテーターが行います。

**エンドポイントが過大請求することはありますか？**
金額を*要求*すること自体は可能です。正しく実装されたクライアントは、署名の前に要求額を上限と
照合します。FrostyFiのノードは上限を超えた時点で拒否し、署名処理に到達しません。

**どのステーブルコインを使いますか？**
実務上はUSDCで、多くはBase上です。ただしプロトコル自体は資産・チェーンに依存しません。

**コードを書く必要はありますか？**
FrostyFiでは不要です。x402 Payはキャンバスにドラッグするノードとして提供されています。
