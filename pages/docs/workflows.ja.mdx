# ワークフローとノードライブラリ

**ワークフロー** は、ドラッグ＆ドロップのキャンバス（`@xyflow/react` で駆動）上で構築する
有向グラフです。各 **ノード** はステップであり、各 **エッジ** はあるノードの
出力から次のノードの入力へとデータを運びます。このページでは、データの流れ方、すべてのノードタイプ、そして
Frosty Engine でワークフローをバックグラウンド実行する方法を説明します。

![キャンバス上のワークフロー — Input → HTTP → LLM → Output、ドキュメント用の注記付き](/screenshots/workflow-canvas.png)

## データの流れ方

すべてのワークフローは同じ形をとります：

```
Input ──► (any nodes) ──► Output
```

- **すべてのワークフローは Input ノードで始まらなければなりません。** これはエントリポイントであり
  検証ゲートでもあります — ウェブフックとスケジューラのトリガーは、その *後* に連鎖します。
- 各ノードは上流ノードの出力から読み取り、自身の出力を生成します。それを
  下流ノードが参照できます。
- **Output** は、ワークフローが返す最終結果（チャットへ、ウェブフックの呼び出し元へ、
  または A2A の支払者へ）を生成します。

中間値を整形・命名するには **Template** ノードと **Set** ノードを、
分岐には **Condition** を、配列を反復処理するには **Loop** を、並列パスを再結合するには **Merge** を使います。

## ノードライブラリ

### コアフロー

| ノード | 機能 |
|------|--------------|
| **Input** | エントリポイント。実行の初期データを受け取る。必須。 |
| **Output** | 終了点。ワークフローの最終結果を生成する。 |
| **Condition** | 比較に基づく if/else 分岐。 |
| **Set** | 後続ノードが使うために、名前付き変数へ値を代入する。 |
| **Merge** | 複数の並列実行パスからのデータを結合する。 |
| **Loop** | 配列を反復処理し、要素ごとにサブワークフローを実行する。 |
| **Wait** | 指定した時間だけ実行を遅延させる。 |
| **Template** | 以前の出力から `{{variable}}` 置換を行ってテキストを生成する。 |
| **Note** | ドキュメント/注釈用のノード（実行への影響なし）。 |

### AI

| ノード | 機能 |
|------|--------------|
| **LLM** | プロンプトで AI モデルを呼び出す（OpenRouter 経由でルーティング）。 |
| **Agent** | ツール、メモリ、多段推論を備えた自律 AI エージェントのステップ。 |
| **Tool** | [MCP](/docs/mcp) ツールを実行する。 |

### Web と連携

| ノード | 機能 |
|------|--------------|
| **HTTP** | 任意のエンドポイントに REST API リクエストを送る。 |
| **Webhook** | インバウンドの HTTP リクエストからワークフローをトリガーする（Frosty Engine を参照）。 |
| **Scheduler** | cron スケジュールでワークフローをトリガーする（Frosty Engine を参照）。 |
| **EmailSend** | SMTP 経由でメールを送信する。 |
| **Telegram** | Telegram のチャット/チャンネルにメッセージを送る。 |
| **Discord** | ウェブフック経由で Discord のチャンネルにメッセージを送る。 |
| **Twilio** | Twilio 経由で SMS と WhatsApp のメッセージを送る。 |
| **RSS** | RSS/Atom フィードを読み取って解析する。 |
| **Twitter** | Twitter/X API に投稿・操作する。 |
| **ChainGPT** | ChainGPT の AI 駆動 Web3 ツール。 |

### メディア

| ノード | 機能 |
|------|--------------|
| **Image** | プロンプトから画像を生成する（OpenRouter 経由でルーティング）。 |
| **Video** | プロンプトから動画を生成する（OpenRouter 経由でルーティング）。 |
| **Voice** | テキスト読み上げと音声認識（TTS / STT）。 |
| **File** | ファイル添付を扱う — ノード間でファイルを読み書き・受け渡しする。 |

### コード

| ノード | 機能 |
|------|--------------|
| **Code** | サンドボックス化された JavaScript を実行する。Frosty Engine では、コードは安全な実行のために `isolated-vm` サンドボックス内で動きます。 |

### ブロックチェーン

| ノード | 機能 |
|------|--------------|
| **Vault** | ThirdWeb Vault によるキー管理 + 署名 — サーバーウォレットを管理し（`getWallet`、`createEoa`、`listEoas`）、署名する（`signMessage`、`signTypedData`、`signTransaction`、`signAuthorization`）ほか、Solana の同等機能も。キーは Vault 内に保持され、生の秘密鍵として貼り付けることはありません。[Vaults](/docs/vaults) を参照。 |
| **EVM** | ThirdWeb v5 SDK による EVM 操作 — 残高の読み取り、コントラクトの読み書き、トランザクション送信、ERC-20/721/1155 の転送、ENS 解決、Uniswap V3 のクォート、ブリッジのステータス、コントラクトのデプロイ、そして **x402 決済**（`x402Payment`、`x402RetryWithPayment`）。マルチチェーン：ThirdWeb 経由で 1700 以上のチェーン。 |
| **Solana** | `@solana/web3.js` による Solana 操作。 |

### DeFi とトレーディング

| ノード | 機能 |
|------|--------------|
| **Uniswap** | EVM チェーン上での Uniswap のスワップとクォート。 |
| **SushiSwap** | EVM チェーン上での SushiSwap のスワップとクォート。 |
| **PancakeSwap** | EVM チェーン上での PancakeSwap のスワップとクォート。 |
| **Jupiter** | Jupiter アグリゲーター経由での Solana のスワップとクォート。 |
| **Hyperliquid** | Hyperliquid の perps/マーケット — 価格、板情報、ポジション（およびトレーディング）。 |

> **生のキーではなく Vault。** FrostyFi は秘密鍵やシードフレーズの貼り付けを求めることは決してありません。
> ブロックチェーンの書き込み操作は ThirdWeb Vault を通じて署名されるため、署名素材は Vault 内に留まり、
> ワークフローの設定には触れません。

## Frosty Engine でのデプロイとスケジュール

キャンバスは構築のためのものです。ワークフローを **バックグラウンドで — ブラウザを開かずに —**
実行するには、**Frosty Engine** にデプロイします。これは Express ベースの実行バックエンドで、各ノードタイプを
ヘッドレス実行に最適化されたエグゼキュータで動かします。

2 種類のトリガータイプが、ワークフローを自律的に実行させます：

- **Scheduler（cron）** — 繰り返しスケジュールでワークフローを実行します。cron スケジュールは
  永続的です：データベースに保存され、エンジンの再起動時に再読み込みされます。
- **Webhook** — 外部サービスがそのウェブフック URL に POST したときにワークフローを実行します。
  ウェブフック呼び出しは、ウェブフックごとのシークレットで認証されます。

バックグラウンド実行（Frosty Engine）は **Pro / Enterprise** 機能です —
[料金](/docs/pricing)を参照してください。

> **注：** 繰り返しの cron スケジュールはエンジンの再起動を生き延びます。一度限り（遅延）のスケジュール
> と実行中の処理は、現在メモリに保持されており、再起動後に再開される保証はありません — 永続的なジョブ
> キューイングはロードマップにあります。時間的にクリティカルな自動化には、
> 繰り返しスケジュールを推奨します。
