# コアコンセプト

FrostyFi には、すべてが「AI」に触れているために混同しやすい少数の構成要素があります。
このページでは、それぞれを正確に定義します。そして — 最も重要なこととして — **アシスタント**と
**エージェント**の間に線を引きます。

## ワークフロー

**ワークフロー** は目玉機能です。ドラッグ＆ドロップのキャンバス上で構築する、ビジュアルでノードベースの
自動化です。ワークフローは、**エッジ**（データフロー）で接続された **ノード**（ステップ）の有向グラフです。
常に **Input** ノードで始まり **Output** ノードで終わります。
その間に、LLM 呼び出し、HTTP リクエスト、条件、コード、ブロックチェーン
操作、ループ、連携を配線します。

ワークフローはノード + エッジとしてデータベースに保存されます。実行方法は 3 通りです：

- **インライン** — チャットから `@mention` されてツールとして実行される。
- **バックグラウンド** — [Frosty Engine](/docs/workflows#frosty-engine) に cron スケジュールで、
  またはウェブフック経由でデプロイされる。
- **エージェントとして** — 外部の呼び出し元が起動できるように公開される（下記の「エージェント」を参照）。

完全なノードライブラリについては、[ワークフローとノード](/docs/workflows)を参照してください。

## アシスタント

**アシスタント** は **推論チャットエキスパート** です。設定済みのペルソナ — 
役割/専門性、システムプロンプト、スキルセット、ツールセット — と考えてください。チャットで `@` を使って
呼び出せます。

主な特性：

- **モデル非依存。** アシスタントは 1 つのモデルに縛られません。ピッカーで選択したモデルなら
  どれでも動作します。
- チャットで **`@mention` 可能。** アシスタントをメンションすると、そのペルソナとスキルが
  会話に注入されます。
- **デプロイできない。** アシスタントはチャットランタイムの中に存在します — ヘッドレスな
  バックグラウンドランタイムを持たないため、直接 x402/A2A/ERC-8004 のエンドポイントには *なりません*。
  アシスタントの挙動をデプロイ可能な単位として必要とする場合は、ワークフローに組み込んでください
  （**Agent ノード** により、ワークフローにアシスタント風の推論を埋め込めます）。

## エージェント

**エージェント** は **デプロイされたワークフローエージェント** です。ライブで呼び出し可能な、オンチェーン ID を持つ
エンドポイントとして公開されたワークフローです。FrostyFi のモデルでは、*「ワークフロー
エージェント」と「A2A エージェント」は同じもの* です — 同じレコードに、デプロイ用のフラグが立っているだけです。

エージェントは次を提供します：

- [A2A](/docs/agents#a2a-protocol) エンドポイントと発見可能な **エージェントカード**。
- オプションの [x402](/docs/agents#x402-payments) による呼び出しごとの USDC 決済。
- オプションの [ERC-8004](/docs/agents#erc-8004-identity--reputation) オンチェーン ID と
  評価。
- [マーケットプレイス](/docs/agents#marketplace)への掲載。

### アシスタント vs. エージェント — 正確な区別

| | **アシスタント** | **エージェント** |
|---|---|---|
| それは何か | 推論チャットのペルソナ | デプロイされたワークフロー |
| ワークフローに裏打ちされる？ | いいえ（`workflowId` は null） | はい（`workflowId` を持つ） |
| どこで動くか | チャットランタイムの中 | ヘッドレス、Frosty Engine 内 |
| チャットで `@mention` 可能？ | はい | いいえ — エージェントエンドポイント経由で呼び出すか、そのワークフローを実行する |
| デプロイできる？ | いいえ | はい — それ *こそ* がエージェントたる所以 |
| x402 / A2A / ERC-8004？ | いいえ | はい |

短く言えば：**アシスタントはチャット内で考えるためのもの、エージェントは他者が呼び出して
支払える、デプロイされたワークフローを実行するためのもの** です。両方の面が、*ワークフローを通じて* 同じ
収益化パスを得ます — アシスタントの能力をワークフローに組み立て、そのワークフローをエージェントとして
デプロイするのです。

## スキル

**スキル** は **アシスタントに注入される、指示のみのドキュメント** です。スキルは
コードでもツールでもありません — アシスタントのシステムプロンプトに追加される、ガイダンス（ベストプラクティス、
手順、ドメイン知識）のブロックです。ユーザーのリクエストが
スキルに合致すると、アシスタントはそのガイダンスに従います。

スキルは、ソフトウェアを書くことなくアシスタントに *やり方* を教える手段です。
アシスタントエディタでスキルをアシスタントに紐付けます。

## MCP サーバー

**MCP サーバー**（[Model Context Protocol](/docs/mcp)）は、**ツール** の外部ソースです。
MCP サーバーを接続すると、チャットとアシスタントに呼び出し可能なツール群（例：
市場データ、決済、Web 取得）が与えられます。

MCP は **リモート専用** です — リモート（HTTP/SSE）の MCP サーバーに接続します。マーケットプレイスは
審査済みのリモートサーバー（例：CoinGecko、Alpha Vantage、Stripe、Etherscan、Blockscout）を提供します。

## テンプレート

**テンプレート** は **複製して使うワークフロー** です。テンプレートギャラリーには、あらかじめ構築された
公開ワークフローが含まれています。**Use template** をクリックすると、その 1 つを（新しいノード
ID とともに）ワークスペースにコピーし、実行してカスタマイズできます。テンプレートは始めるのに最速の手段です —
[Getting Started](/docs/getting-started#4-create-your-first-workflow-from-a-template)を参照してください。
