# x402란 무엇인가?

**x402는 HTTP 요청을 보내는 바로 그 순간에 결제를 끝내는 개방형 결제 프로토콜입니다.**
오랫동안 쓰이지 않던 `402 Payment Required` 상태 코드를 되살립니다. 서버가 요청에 대해 `402`와
가격을 응답하면, 클라이언트가 스테이블코인 송금에 서명하고, 결제 증명을 붙여 같은 요청을 다시
보냅니다.

API 키도, 계정 가입도, 구독도, 영업 미팅도 필요 없습니다. **결제 자체가 인증 수단입니다.**

이 점이 가장 크게 작용하는 대상이 **AI 에이전트**입니다. 사람이 미리 키를 발급해 주지 않아도
에이전트가 필요한 데이터와 추론을 직접 구매할 수 있게 됩니다.

## x402 요청의 흐름

1. 클라이언트가 유료 엔드포인트를 평소처럼 호출합니다.
2. 서버가 **`402 Payment Required`**와 함께 `accepts` 목록(금액, 자산, 네트워크, 수취 주소)을
   반환합니다.
3. 클라이언트는 요구 금액을 자신의 지출 한도와 대조한 뒤, 정확히 그 금액에 대해
   **EIP-3009 `TransferWithAuthorization`**에 서명합니다.
4. 클라이언트가 `PAYMENT-SIGNATURE` 헤더에 서명된 승인을 담아 **완전히 동일한 요청**을 재전송합니다.
5. 서버(또는 파실리테이터)가 온체인에서 정산하고 실제 응답을 반환합니다.

핵심은 두 가지입니다. 서명하는 대상이 트랜잭션이 아니라 **승인(authorization)**이라는 점 —
따라서 트랜잭션을 전송하고 가스비를 내는 쪽은 *서버*이고, 에이전트는 네이티브 가스 토큰을 보유할
필요가 없습니다. 그리고 4단계가 1단계를 바이트 단위로 그대로 재전송하는 것이기 때문에, 기존 API를
재설계하지 않고도 x402를 붙일 수 있습니다.

## 비용에 대한 솔직한 이야기

x402는 추론을 **저렴하게 만들어 주지 않습니다.** 호출당 비용은 오히려 **더 비싼** 경우가 많습니다.

일반적인 x402 엔드포인트는 요청마다 고정 수수료를 부과하는데, 이 수수료가 실제 연산 비용을 크게
웃도는 경우가 흔합니다. 1센트도 안 되는 비용으로 처리할 수 있는 호출에 0.3센트 이상의 수수료가
붙기도 합니다. **가격만 최적화한다면 제공업체에 선불 계정을 두는 편이 여전히 유리합니다.**

x402로 얻는 것은 가격이 아니라 **자율성**입니다. USDC를 보유한 에이전트는 x402를 지원하는 어떤
제공업체에든, 계정 없이, 키 교체 없이, 사람의 개입 없이 지불할 수 있습니다. 무인으로 계속 도는
에이전트에게 이것은 "계속 동작한다"와 "멈춘다"의 차이입니다.

x402를 비용 절감책으로 파는 설명은 경계하세요. 이것은 **할인이 아니라 새로운 능력**입니다.

## 실제로 정산된 결제

도식이 아니라 저희 로그에서 가져온 실제 사례입니다.

FrostyFi 워크플로가 유료 추론 엔드포인트를 호출했고 엔드포인트는 `402`를 반환했습니다. 에이전트의
Vault 보관 지갑이 `$0.05` 한도 안에서 EIP-3009 승인에 서명하고 요청을 재전송했습니다. 응답이
돌아왔고 송금은 **Base**에서 정산되었습니다.

| 항목 | 값 |
| --- | --- |
| 지불 금액 | `$0.00333` USDC |
| 네트워크 | `eip155:8453` (Base) |
| 정산 트랜잭션 | [`0x17942efd…4f2d64254`](https://basescan.org/tx/0x17942efd0ae1fb7a88b8ce0e605e1beb53e90c2f1ba0770c0874e3a4f2d64254) |
| 총 소요 시간 | 7.02초 |

이 흐름 어디에도 API 키는 존재하지 않았습니다. 에이전트가 자기 추론을 직접 구매한 것입니다.

## FrostyFi에서의 x402

FrostyFi는 프로토콜의 **지불하는 쪽**과 **과금하는 쪽**을 모두 지원합니다.

**지불.** **x402 Pay** 노드는 임의의 x402 엔드포인트를 호출하고 챌린지를 스스로 처리합니다.
URL과 지출 한도만 지정하면 402 해석, 서명, 재전송을 노드가 담당합니다. 키는
[thirdweb Vault](/docs/vaults)에 보관되어 워크플로가 개인키를 볼 일이 없고, 한도 검사는 서명
**이전**에 수행되므로 악의적인 엔드포인트가 지갑을 비울 수 없습니다.

**과금.** 워크플로를 [에이전트](/docs/agents)로 게시하고 호출당 가격을 설정하세요. 호출자는
USDC로 지불하고, 정산은 온체인에서 이루어지며, 에이전트는
[ERC-8004](/docs/agents#erc-8004-identity--reputation) 온체인 신원과 평판을 가질 수 있습니다.

이 둘이 합쳐지면 루프가 닫힙니다. USDC를 버는 에이전트가 그 USDC로 자기 추론을 사고, 두 거래
어디에도 사람은 개입하지 않습니다.

## 자주 묻는 질문

**x402는 블록체인이나 토큰인가요?**
둘 다 아닙니다. HTTP 규약입니다. 정산은 엔드포인트가 받아들이는 체인에서 이루어지며 보통 Base
위의 USDC이지만, "x402 토큰" 같은 것은 없습니다.

**에이전트에 가스비가 필요한가요?**
필요 없습니다. EIP-3009 덕분에 지불자는 승인에 서명만 하고, 트랜잭션 전송과 가스비는 서버 또는
파실리테이터가 부담합니다.

**엔드포인트가 과다 청구할 수 있나요?**
금액을 *요구*하는 것 자체는 가능합니다. 올바른 클라이언트는 서명 전에 요구 금액을 하드 한도와
대조합니다. FrostyFi 노드는 한도를 넘으면 서명 단계에 도달하기도 전에 거부합니다.

**어떤 스테이블코인을 쓰나요?**
실무에서는 USDC이며 대부분 Base 위에서 이루어집니다. 다만 프로토콜 자체는 자산과 체인에
비종속적입니다.

**코드를 작성해야 하나요?**
FrostyFi에서는 필요 없습니다. x402 Pay는 캔버스에 끌어다 놓는 노드입니다.
